# G2 runtime fixture and drift ownership

G2 fixtures are deterministic contract evidence, not editable sample levels. Generated files must
never be modified by hand.

## Existing authoritative transport

The authoritative G2 reference transport is:

```text
examples/g1-workflow/reference/scene-manifest-v0.3.luau
```

Its owner is `tools/g1-workflow-fixture-content.ts`. The authoritative drift command is:

```text
npm run layout:workflow:fixtures:check
```

`npm run g2:decisions:check` independently compares that exact file with
`expectedG1WorkflowFixtures()` and verifies the owner command has not been redirected. The matching
JSON manifest and authority/source artifacts in the same reference directory remain the diagnostic
preimage chain.

`roblox/generated/G1cReferenceManifest.luau` is not a G2 runtime fixture. It remains historical G1c
validator coverage and is intentionally not byte-equivalent to the completed G1d workflow output.

## Future Rojo-owned fixture set

G2b/G2c will introduce one content function, proposed as
`tools/g2-runtime-fixture-content.ts`, and matching generate/check commands. The command names and
files do not exist in G2a. When introduced, the check command—not the generate command—must be added
to `npm run validate`.

Proposed generated destinations and owners:

| `reference`               | `roblox/generated/G2ReferenceManifestV03.luau`             | Exact bytes from the authoritative G1d transport                                  | 15 stages, checkpoints, hazards, replacement baseline              | G2b          |

If the current G1 authorities cannot generate a required coverage shape, G2 must add a deterministic
test-fixture producer over valid committed contracts; it must not mutate a manifest after hashing or
change G1 contracts. Discovery of a contract defect stops the phase for review as required by G2a.

## Scenario and failure ownership

These cases do not need separate malformed manifest transports:

| Scenario              | Evidence owner                                         | Rule                                                                                  |
| --------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Replacement success   | Reference → `replacement-b` in fake runtime and Studio | Both inputs remain independently valid and drift-checked                              |
| Replacement failure   | Deterministic factory/session failure injector         | Inject before or at a documented transaction boundary; never corrupt a hash           |
| Stale callbacks       | Runtime-session fake event scheduler                   | Queue valid old-generation CharacterAdded/touch callbacks, replace, then release them |
| Two players           | Fake Players service plus two-client Studio run        | State keyed by player and manifest hash                                               |
| Same-manifest rebuild | Reference fixture loaded into two runtime generations  | Same manifest hash, distinct runtime generation tokens                                |

Failure injection is test-only dependency injection and cannot be enabled by manifest data or the
production bootstrap.

## Drift and review rules

- Generation runs in a temporary directory or through in-memory expected-content helpers.
- Checks compare exact UTF-8 bytes; semantic JSON equality is insufficient for Luau transport drift.
- The reference transport must equal the G1d owner output byte-for-byte.
- Fixture indexes record fixture ID, manifest hash, stage/checkpoint/object counts, and source
  authority hashes.
- Every fixture change shows the source/authority change and regenerated outputs in one PR.
- `roblox/generated` remains generated-only; reviewers reject hand edits.
- The active `roblox/default.project.json` does not include a `0.3` fixture before the final cutover.

## G2a coverage

G2a commits specifications and exact-reference drift checks only. It does not add the proposed
generated destinations, a G2 Rojo project, runtime construction, or Studio automation.
