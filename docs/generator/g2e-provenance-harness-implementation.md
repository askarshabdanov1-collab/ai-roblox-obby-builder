## Root cause and repair

The stale value `9a92540aad3183342096501f268eb1f966d640bf` was a literal in the local
`environment` table in `roblox/g2e/G2eAcceptanceBootstrap.server.luau`. Rojo copied that bootstrap
directly into the G2e place, and `G2eAcceptanceHarness.emitMeasurement` copied the literal into every
`[G2 runtime measurement]` record. It was neither generated provenance nor fixture metadata.

`npm run roblox:g2e:build` now runs `tools/prepare-g2e-build.ts`. The preparation step resolves and
validates one source commit, writes the ignored deterministic module
`build/g2e-provenance/G2eBuildProvenance.luau`, and Rojo maps that module into the acceptance place.
Studio reads only the embedded module; it never invokes Git, the network, or a clock.

The provenance contract is:

1. If `G2E_REPOSITORY_COMMIT` is present, it is the explicit release/source commit and takes
   precedence over Git.
2. Otherwise the preparation step uses `git rev-parse HEAD^{commit}`.
3. Both sources must be exactly 40 lowercase hexadecimal characters. Uppercase, short, malformed,
   or empty values fail with a typed `g2e-provenance-*` error.
4. If Git metadata is unavailable and no override is supplied, the build fails closed. There is no
   fallback commit.
5. Generated bytes contain only schema `g2e-build-provenance-v1` and `repositoryCommit`; no branch,
   timestamp, username, local path, or secret is embedded.
6. Equal commit inputs produce equal provenance bytes. Changing only the commit changes the module
   and therefore the place SHA-256.

The field is a source/release identity, not a claim that a committed `.rbxlx` embeds the SHA of a
commit containing that same binary. The repository ignores `.rbxlx` and `build/`, so no
self-referential artifact commit is required.

The focused automated gate is `npm run g2e:provenance:test`, and `npm run validate` invokes it. The
eight cases cover Git-derived identity, explicit-override precedence, malformed and uppercase
overrides, absent Git metadata, identical-input determinism, changed output for changed provenance,
metadata exclusion, and absence of the historical fallback.

## Bounded acceptance controls

The acceptance-only code now implements all six harness groups identified by the remaining-gap
audit. No file under `roblox/src` changed.

- **H-01:** bootstrap exposes controls with zero active roots. The first official command claims the
  sole cold build for the server; manual builds are labelled `manual` and invalidate later cold
  claims. A fresh bootstrap state is the only counter reset.
- **H-02:** every BindableFunction returns `g2e-control-result-v1`, containing fixed primitive keys.
  Runtime results, Instances, functions, threads, cyclic tables, and arbitrary callback values do
  not cross the control boundary.
- **H-03:** `g2-studio-measurement-v2` adds active-root count, monotonic start/end, heap availability,
  checkpoint/kill/finish/session/CharacterAdded/coordinator connection counts, explicit
  PlayerAdded/PlayerRemoving counts, and a reconcilable total.
- **H-04:** the static sequence builds and inspects wedge and decorative fixtures, checks safe-route
  exclusion, records exact Part/helper properties in deterministic object-ID order, and restores
  reference.
- **H-05:** narrow placement, finish-isolation, same/different-hash progress, and stale
  CharacterAdded/checkpoint/kill/finish observations emit fixed-schema receipts while exercising
  existing runtime behavior.
- **H-06:** three isolated acceptance-only ownership scenarios verify unowned, ambiguous, and
  other-version refusal and restore the original scene after each case.

The official run indices are cold `1`, repeated `1..5`, and replacement `1,2`. Functional and
static follow-up builds have their own `functional` and `static` labels and cannot be confused with
official cold/repeated evidence.
