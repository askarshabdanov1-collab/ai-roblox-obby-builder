## Settled versus deferred

Settled: invariant precedence; discriminated metric provenance; content-addressed catalog/profile;
named non-self-referential hash domains; E1 no aggregate; immutable availability records;
E1a/E1b/E1c boundaries; and screenshot protocol status as draft.

Deferred with explicit gates: a physics proof standard; Studio transport and multiplayer feasibility;
final screenshot environment/profile values; visual worker/model selection; dataset legal approvals;
calibrated thresholds/weights; analytics cohorts/privacy thresholds; rater policy; desktop packaging;
and a correction-patch contract.

## Final hash-preimage re-audit corrections

The first focused correction defined the main configuration, execution, calculation, evidence, and
report preimages. The final focused audit then identified six remaining documentation
inconsistencies; closure was withheld until all six were corrected:

| Final issue                             | Correction and exact source                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Undefined `planHash`                    | Removed from [EvaluationRun and calculation preimages](contracts.md#execution-and-calculation-preimage-types), [architecture reproducibility identity](architecture.md#reproducibility-identity), [evidence graph](evidence-and-studio.md#evidence-graph), and [API responses](api-and-repository.md#evaluate_obby). `configurationHash`, computed only from `EvaluationPlanConfigurationPreimage`, is the sole deterministic EvaluationPlan identity. |
| Request identity was not named          | [Contracts](contracts.md#configuration-preimage-types) define `evaluationRequestHash` and `EvaluationRequestPreimage`; [API idempotency](api-and-repository.md#creation-and-idempotency) uses the exact name and fixed semantic request comparison.                                                                                                                                                                                                    |
| Unnamed availability/tombstone identity | [Contracts](contracts.md#evidence-availability-and-immutable-reports) define `availabilityRecordHash`, `AvailabilityRecordPreimage`, immutable supersession/conflict rules, semantic effective time, and authority identity. The corrected contract retains `obby-canonical-json-v1`, exhaustive fixed evidence-kind rules,

closed at the documentation-contract level only; no implementation or computed test vector is
